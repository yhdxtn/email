# 给代码生成 AI 的主提示词：实现 Astrogate 自托管邮件管理平台

你是一名资深全栈工程师、SRE 和应用安全工程师。请根据本提示词及同目录规格文件，**实际构建一套可运行、可自托管的开源邮件系统管理后台**，而不是只写方案、原型或静态页面。

## 任务目标

实现一个名为 **Astrogate Mail Admin** 的完整管理平台。管理员部署后，可通过网页完成邮件域配置、邮箱账号及别名管理、系统邮件发送、DNS 配置/检测、服务器健康监控、日志查看、备份/恢复和安装向导。平台需要先支持导入并管理已经运行的 Astrogate 邮件服务器，不得默认重装生产机。

阅读并遵守同目录中的：

- `PRODUCT-REQUIREMENTS.md`
- `ARCHITECTURE-AND-API.md`
- `DEPLOYMENT-DNS-BACKUP.md`
- `SECURITY-AND-ACCEPTANCE.md`

如果规格之间有冲突，以安全要求优先，并在实现说明中记录决定。信息不足时选择安全、可逆的默认值，列出假设；不要停止在提问或空泛计划上。

## 技术栈建议

除非现有仓库已选定其他成熟技术栈，使用：

- 后端：Java 21、Spring Boot 3、Spring Security、Flyway。
- 前端：Vue 3、TypeScript、Vite、可访问性良好的组件库。
- 管理数据：PostgreSQL（或 MySQL 8；选一种并固定，不能同时提供未验证的两套实现）。
- 队列/异步工作：优先使用数据库任务队列或轻量 Redis；MVP 不强制额外集群组件。
- 部署：Docker Compose 管理控制面；邮件服务器上的本机 Agent 独立安装为 systemd 服务。
- 测试：后端单元/集成测试、前端测试、API 安全测试、Docker Compose smoke test。
- License：Apache-2.0 或 MIT，并在仓库中明确标注。

也可以选择当前仓库已存在的成熟栈，但必须解释理由、锁定版本，并完整实现测试与部署，不要只生成混搭样例。

2. 实现真实数据库模型、后端业务逻辑、前端管理页面、身份认证、授权、审计、任务队列、DNS provider adapter、邮件节点 Agent、配置迁移、测试、容器文件和完整文档。
3. 每个页面必须连接真实后端 API；不得交付仅有演示数据或按钮无行为的前端。
4. 运行格式检查、静态检查、所有自动化测试、镜像构建和全新空数据库初始化验证。修复失败后再报告。

## 必须实现的系统功能

### A. 安装向导与系统概览

- 首次登录强制创建唯一初始管理员，使用安全随机初始化口令或一次性 setup token；部署后立即禁用 setup 页面。
- 引导设置组织/域名、邮件主机名、公网 IP、DNS provider、SMTP relay 策略、时区、告警收件人、备份目标和管理访问限制。
- 每一步有预检、配置预览、验证、保存及回滚说明。
- 首页显示邮件服务、DNS、证书、备份、磁盘、队列和最近失败任务状态；每个状态可点开诊断原因和修复建议。

### B. 邮箱与域管理

- 管理邮件域、邮箱账户、别名和转发；创建、改密、暂停、恢复、调整配额、删除（延迟清理/可恢复）操作均有审计。
- 邮箱账户与网站用户账号、后台管理员账号使用不同实体、凭据和权限，不可混用。
- 用户网站注册不得自动创建邮箱，除非管理员显式启用经验证的策略。
- 邮箱密码在输入后只形成适配邮件节点认证格式的安全哈希；后台永不回显原密码。
- 页面显示配额使用量、最后登录/失败情况（可用则展示）、账户状态和对应邮件节点。
- 初始适配现有 Postfix/Dovecot 结构。Agent 管理采用版本化适配器，不得假定供应商 API 或特定路径未经检查就存在。

### C. 邮件发送与投递

- 管理员可从受限发送页面向明确填写的测试收件人发单封邮件，支持纯文本/安全 HTML、主题、有限附件、发件人策略、预览及确认。
- 不把后台变成匿名群发服务：强制认证、允许域名、按管理员和目的地址限速、每日上限、附件大小限制、审计发件人/收件人/Message-ID/结果，不记录正文和秘密。
- 展示队列深度、最近投递错误、退信/SMTP 状态、重试状态；提供受控的重试/删除队列操作并审计。
- 所有 TLS 校验证书和 SMTP 错误分开显示。SMTP 被接受不代表收件箱送达；外部验收需人工收件/回信。
- Roundcube 可作为用户邮件客户端链接；除非规格另行要求，不要重复实现完整 IMAP 网页邮箱。

### D. 域名与 DNS 管理

- 后台维护域名、主机名、目标 IP、MX、SPF、DKIM、DMARC、autoconfig/autodiscover 等所需记录的期望状态，并提供逐条检测、传播状态、TTL 和前后差异。
- 设计 `DnsProvider` 插件接口。先实现手动 DNS provider，和一个有官方 API 且能测试的 provider adapter；provider 由用户在 UI 明确选择并配置最小权限 API token。
- 不得因为 NameSilo 是注册商就假定 DNS 也托管在 NameSilo。显示实际 NS/权威 provider，并允许域名注册商与 DNS provider 分开配置。
- DNS 写操作必须先生成 dry-run 差异，显示影响的记录；用户二次确认后执行，保存快照并提供回滚。未配置 API 或 API 无权时清晰显示“请手工修改”，提供逐条复制的记录模板与传播检查。
- PTR/rDNS 通常由 IP/VPS 服务商管理。后台检查当前 PTR 并给出供应商操作说明，不将 PTR 假装成普通 DNS Zone 记录。
- MX、mail A、网站 A、SPF、DKIM、DMARC 明确分区，网站 A 不得被邮件向导覆盖。

### E. 监控、告警和诊断

- 定期探测 DNS A/MX/TXT、SPF/DKIM/DMARC、PTR 与正向匹配、TCP 25/587/993、SMTP STARTTLS、TLS 证书域名/链/有效期、IMAP 合成登录、Postfix/Dovecot/数据库/Agent、队列、磁盘和 inode。
- 将“端口可连接”“SMTP 已接受”“对方服务器接受”“人工确认收件箱”分成不同状态，不伪造送达保证。
- Gmail 垃圾箱/域名声誉无法由本系统完全保证，展示为外部观察项并支持人工记录，不显示虚假绿灯。
- 告警支持邮件/Webhook 可选，去重、静默期和恢复通知；告警文本不含正文、密码、Token、私钥或完整个人邮件内容。
- 保留有界的任务/探测历史，提供失败原因和操作人。

### F. 服务器与 Agent

- 管理平台不得通过网页参数拼接 SSH/shell 命令，不得暴露 root shell、任意文件读写或任意 SQL。
- 邮件节点 Agent 使用 mTLS/签名任务与短期令牌，绑定具体安装实例；提供版本化、固定白名单 RPC，例如健康检查、列出账户状态、添加/停用账户、更新密码哈希、重载允许的服务、运行 DNS/TLS/端口诊断、启动备份任务。
- Agent 每个动作有参数 schema、域名和路径白名单、超时、输出过滤、幂等性键及审计关联 ID；拒绝未知方法。优先采用不可直接执行任意命令的窄接口和 root-owned helper。
- 管理平台与 Agent 断连时，明确显示离线，禁止将排队状态伪装成功。
- 安装、升级、重建必须分阶段，可回滚；生产节点首次导入只读扫描并展示变化计划，不能默认覆盖文件或重装组件。

### G. 网站注册用户管理（与邮箱账号分开）

- 定义可选的 Astrogate 应用用户目录或只读外部用户目录集成；不要擅自写入真实网站数据库。
- 在接入应用用户管理前，需要显式配置连接器和映射；权限仅限所需操作。
- 管理页面至少支持搜索、查看验证状态、冻结/解冻、触发重置流程、导出审计事件；不得查看密码、明文验证码或邮箱正文。
- 用户验证流程的 5 分钟验证码、一次性消费、尝试次数和速率限制属于 Astrogate 应用后端职责；邮件管理平台只负责受限 SMTP 投递和状态跟踪。

### H. 备份、恢复与重新部署

- 备份包含邮件 Maildir、邮件域/账户/别名、Postfix/Dovecot/OpenDKIM/Roundcube 配置和数据库、后台数据库、必要 TLS/续期元数据及密钥恢复清单。
- 备份客户端加密，密钥与归档分开存储；支持本地/兼容 S3 目标、保留轮换、完整性校验、最近备份告警和可视化恢复演练。
- 恢复先在隔离环境验证归档、版本、UID/GID、数据库迁移、DKIM 密钥和证书续期，再展示将改动的服务/文件/DNS；明确警告避免覆盖新邮件。
- 提供 Debian/Ubuntu 受支持版本清单、从空机部署步骤、端口/防火墙表、TLS/自动续期、DNS 配置、当前服务器导入步骤、升级和回滚文档。
- DNS provider API token、TLS 私钥、DKIM 私钥、SMTP 凭据、Agent 私钥不进镜像、源码、ZIP 示例或日志。

## 账户/权限最低要求

角色至少有：`Owner`、`MailAdmin`、`DnsAdmin`、`Auditor`、`Operator`。最小权限默认拒绝。当前管理入口采用用户名和强密码直接登录；强制 HTTPS、安全 Cookie、CSRF 防护、同站策略、登录限速、会话吊销和部署级 IP allowlist。所有高危动作（DNS 写入、账户删除、队列删除、恢复、Agent key 轮换）要求近期重新输入管理员密码并再次确认。

## 必须通过的验收用例

1. 新环境可启动，首次管理员设置成功，setup token 之后不可再用。
2. 未认证请求不能访问 API；无权限角色不能操作 DNS、账户、备份；密码错误、登录限速和高危操作密码重认证均有回归测试。
3. 新建/暂停/恢复邮箱经过 Agent 完成，参数校验、幂等、审计及失败回滚均验证；密钥/哈希不能从 API 读回。
4. 手动 DNS 模式能精确列出 A/MX/SPF/DKIM/DMARC，自动 DNS 模式先 dry-run 后确认并有回滚；网站 A 记录不被改动。
5. 指定测试收件人发送邮件可见状态和 Message-ID，限制群发并遮蔽正文；不会把 SMTP 接受显示为 inbox 到达。
6. 探测能区别 DNS 缺记录、端口阻断、TLS 错误、服务停止、队列积压、磁盘告警、Agent 离线。
7. 备份加密、校验失败会阻止恢复；测试恢复不会覆盖源节点；恢复演练可生成审计报告。
8. 日志和构建制品扫描无秘密，无任意 shell/SQL/webhook SSRF 路径，安全测试有负向用例。
9. OpenAPI 文档与实际接口匹配；Docker Compose 可从空卷初始化并通过 smoke tests。
