# 运维、备份和故障恢复

## 当前管理入口与证书维护（2026-10-16）

`admin.astrogate.sbs` 的 A 记录指向 `23.94.184.57`，管理 HTTPS 返回 HTTP 200。线上请求链为 HAProxy（TLS SNI 分流）→ Nginx `127.0.0.1:9443` → 控制面 `127.0.0.1:8088`；邮件入口仍为 `mail.astrogate.sbs`。管理证书由手动 DNS-01 签发，有效期截至 **2027-01-14**，NameSilo API 自动续期尚未配置。请在约 **2026-12-15** 开始续期，按当前 ACME 客户端流程人工完成 DNS-01 挑战，并验证公网证书链、主机名、到期日、管理页面及邮件站点回归；完成后记录验证日期和结果。不要把 NameSilo 登录信息、API key、ACME 账户密钥或私钥写入仓库或运维文档。

入口可达不表示后台已可管理邮件。当前 setup 状态为 `needsSetup=false`、`productionAccepted=false`，管理员已初始化且可使用用户名和密码登录。后台入口已可访问；邮件节点 Agent、DNS、SMTP 与真实邮箱操作仍须分阶段验收，见 `docs/ACCEPTANCE.md`。

管理入口的 HAProxy→Nginx:9443 拓扑与 `deploy/nginx-mail-admin.conf.example` 假设的 Nginx 公网 80/443 监听不同。示例不可直接启用到现网；证书续期或代理改动时应先检查每一跳的监听、SNI、Host 和客户端地址头行为，保留配置备份并执行 Nginx/HAProxy 配置检查及邮件站点回归。

## 可信反向代理与来源 IP

应用默认不信任用户自行发送的客户端 IP 转发头。只有在实际部署的应用版本支持后，才配置 `ADMIN_TRUSTED_PROXY_CIDRS`，并且只填写直接连接应用的受控反向代理网段；应用只接受该可信代理覆盖写入的单值 `X-Real-IP`。核对代理拓扑中每一跳的来源和头覆盖规则，再通过可信与非可信网络验证 IP allowlist。禁止 `0.0.0.0/0`、`::/0`、任意来源网段或信任所有代理头。当前服务器实际运行的代码是否包含该配置能力，应以已部署版本为准；文档变更不表示该功能已上线。

## 状态与重试

任务保存在 PostgreSQL，外部执行前检查管理员当前授权、节点只读状态、白名单方法和参数。排队超过十五分钟的任务拒绝执行，避免很久之前提交的邮件突然被发送。并发认领使用行锁与 SKIP LOCKED；单进程定时执行器适合低量控制面，未做 HA/吞吐量验收。

queued/running/success/failed/unknown 是不同状态。SMTP 或 Agent 超时、中断后结果可能已发生，不能盲目自动重试。Agent 用持久幂等账本阻止相同任务再次生效；同一个幂等键换参数会冲突。对 unknown 应先只读读取外部状态并保留审计关联。

对 interrupted 任务保留结果未知，页面不显示为成功。Agent 账本有最大条数，达到限制会拒绝继续，不会自动删除旧记录后失去重放保护。业务任务/审计全生命周期保留策略尚需补齐；本版只对部分探测、会话、计划秘密提供清理。不要在运行中删除账本或随意重置实例 ID。

## 当前备份能力的准确边界

已实现：对**部署配置明确声明的本地文件集合**打包，加密写入本地备份目录，验证认证标签/manifest/文件 SHA-256，之后在新的随机隔离目录提取演练。密钥独立文件，不放入归档；密钥丢失将无法恢复。Agent 账本使用 SQLite backup API 取得副本，而不是直接复制正在写入的数据库文件。

默认上限 256 MiB、20,000 文件、80 秒，面向测试/小型受限集合，不适合作为大容量 Maildir 唯一备份。应根据离线演练结果设计专业大容量备份，而不是只调大参数。文件遍历拒绝符号链接/特殊文件，文件过程中有变化会失败；没有快照文件系统级一致性保证。空目录、正在增长的邮件和各数据库之间的时间一致性仍需额外处理。

**未实现：S3 目标、自动保留轮换、控制面 PostgreSQL 自动 dump、Roundcube/MySQL 一致性 dump、全邮件栈配置与 DKIM/TLS 密钥恢复编排、完整服务启动验证。** 当前“校验/演练成功”只是文件归档范围内成功，不表示已恢复整个邮箱系统。

## 必须额外维护的完整灾备清单

在独立的合格备份流程中保存：Maildir 及其 UID/GID/权限；邮件域/账号/别名及原认证数据；Postfix/Dovecot/OpenDKIM/Roundcube 配置；相关数据库一致性备份；控制面 PostgreSQL；DKIM/TLS 与自动续期元数据；Master key、Agent/HMAC/backup key 的独立恢复清单。禁止把这些秘密加入源码 ZIP 或不加密的共享文档。

真正恢复前在隔离网络克隆目标上核对归档、版本、UID/GID、数据库迁移、DKIM 签名、TLS 证书续期、IMAP 登录、收发与 DNS 差异。不得直接覆盖包含新邮件的源节点。本项目没有提供可安全自动执行该完整流程的脚本，因此不能声称九条验收全部通过。

## 回滚

控制面源码/镜像：保留上一个已验收版本和对应数据库备份；数据库 schema 回滚不能通过盲目切换镜像保证。此版仅有 V1 新库迁移，没有经过生产升级/降级验证。先在克隆数据库验证再安排维护。

邮箱 maps：适配器对允许修改的 maps 做原子替换与异常回滚，保留 Maildir。某些进程重启/外部工具同时写入导致的窗口仍必须实机验证。检测到原文件漂移会拒绝写，不会把未知原格式强行接管。

DNS：只恢复该动作保存的邮件管理记录快照，检查外部漂移，重新认证并确认，不能覆盖网站记录。

## 权限 helper

helper 默认关闭，Web API 不接受任意命令。`root_helper.py` 只接受固定服务名或合法单个 queue ID，使用固定路径 argv，不使用 shell。`deploy/helper-sudoers.example` 是人工审查模板，不是自动安装授权。

systemd 默认 `NoNewPrivileges=true`，因此不会默认通过 sudo 提权。需要特权 queue/reload 时必须额外设计并审核窄 helper 授权及适用的 drop-in；没有执行过真实 root helper 验收。不要为了“按钮能点”放开任意 sudo 或整个服务 root 运行。

## 手工投递验收

在受限测试名单中逐一检查 SMTP STARTTLS/证书、提交服务器接受、外部服务器接收、人工收件箱/垃圾箱观察与回信。不同收件服务分别记录日期和 Message-ID，不保存完整正文到审计。Gmail/QQ 垃圾邮件状态和域名/IP 声誉不是平台可完全保证的指标。
